# API coverage and gaps

All paths below use `/api/v1`. Existing authentication contracts were preserved.

| Contract | Status / use |
|---|---|
| GET public/services; GET public/services/{slug} | Existing catalogue; customer snapshot reads list with detail metadata |
| GET/PATCH users/me; users/me/profile | Existing profile |
| users/me/addresses | Existing address CRUD/default selection |
| users/me/payment-methods | Existing preferences only; registering a method never charges |
| users/me/settings, reviews, statistics | Existing authenticated account APIs |
| GET public/booking-schemas | NEW: eight version-1 schemas and explicit supported service slugs |
| GET users/me/booking-draft | NEW: current user's persisted draft or null |
| PUT users/me/booking-draft | NEW: validated partial requirements, active VND service, own address, serialized JSON |
| DELETE users/me/booking-draft | NEW: current user's draft only |

Draft writes serialize on the owning user row and upsert one draft per Customer. Endpoints require CUSTOMER authority. Flyway V8 adds one table referencing users; existing tables/contracts are unchanged. OpenAPI annotations are generated by the existing springdoc integration. There is no draft-to-task side effect.

Added pricing contracts: see taskly-v3-admin-pricing.md for Admin rule CRUD and Customer quote create/revalidate endpoints, V9 migration and version/expiry behavior.

Missing P0 contracts: idempotent task creation, sandbox payment intents/status/webhook verification, matching/assignment, task reads and lifecycle mutations, completion confirmation. A tasks entity/migration exists, but a table alone is not a mobile contract.

Other gaps: chat, notification inbox, support/disputes, cancellation fee preview, change requests/adjustments, no-show/rematch, media uploads, service coverage, favorites, recurring, vouchers/rewards, session management screens and account deletion. Do not infer success or balances from prototype localStorage.

Admin now supplies price rules and fees per the user decision. Next financial implementation needs the reservation/charge order, refund/discount rules and a sandbox provider contract. No HTML prices, escrow semantics or cancellation fees were adopted as real rules.
